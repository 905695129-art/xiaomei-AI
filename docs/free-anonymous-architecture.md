# Heart Studio 免费免注册版本：产品与技术决策

状态：已确认的目标架构；本文件不代表功能已经实现或网站已经上线。

## 产品定位

Heart Studio 是免费、免注册、免登录、免下载的心意互动创作工具。平台不收取任何费用，不代收款、不验证付款、不分账，也不建立平台支付订单。

## 核心用户流程

1. 女生打开创作页面，在本机浏览器中创建一份体验。
2. 设置主题、称呼/头像、邀请函、关卡标题与提示、每关金额展示、私密内容，以及可选的图片/语音/视频和自己的收款二维码。
3. 点击生成分享链接。系统生成高熵随机分享令牌；链接不直接包含私密内容。
4. 男生无需账户或下载，通过分享链接打开邀请函，逐关查看内容和互动。
5. 每关可显示女生填写的金额和她提供的收款二维码。页面必须清楚说明：付款由双方在微信/支付宝等外部渠道自行完成，Heart Studio 不收款、不核验付款，扫码付款不会自动解锁下一关。
6. 体验完成后显示温柔的结束页；不生成或声称生成平台订单。

## 数据保存原则

“不永久保存”是目标，但分享链接需要在女生关闭页面后仍可从另一台设备打开，因此体验数据和媒体必须在分享有效期内暂存于服务端。不能同时承诺“完全不保存任何数据”和“异地分享链接长期可访问”。

默认建议生命周期（需产品确认后作为正式配置）：
- 未完成体验：创建后 7 天过期。
- 完成体验：完成后 24 小时清理。
- 女生创建端提供主动删除入口；删除后分享链接立即失效。
- 媒体与体验 JSON 使用相同或更短的生命周期；清理任务需删除对象存储文件及数据库记录。
- 分享令牌使用密码学安全随机数，数据库只保存令牌哈希；接口限流，响应不泄露体验是否存在以外的信息。

## 最小技术架构

- 前端：沿用现有 Next.js 与已认可的甜美粉色交互界面；手机优先，弹窗和逐关动画保留。
- 匿名创建：不再要求邮箱、密码、账户或登录会话。创建端只在当前浏览器保存一个随机管理密钥，用于管理/删除自己创建的体验；服务端仅保存该密钥的哈希。
- 体验数据：临时数据库记录（体验元数据、关卡、二维码/媒体引用、创建/过期/完成时间）。
- 媒体：私有对象存储、限文件类型与大小、短期签名上传/读取；不使用公开永久 URL。
- 分享：随机令牌链接；男方只需持有链接，不注册。
- 生命周期：定时清理任务 + 读取时过期校验；完成、过期或主动删除均令分享链接失效。
- 付款：只展示创作者自行提供的二维码和金额文字；不集成微信支付/支付宝支付 API，不保存付款状态，不做支付成功判断。

## 必须移除或停用的旧产品模块

当前 main 分支包含邮箱注册/登录、创作者账户、订单与购买历史、买家会话、entitlement、真实支付预留、邮箱验证/找回密码等商业平台架构。这些不属于新产品范围。重构时需逐项停用并移除 UI/API/数据库依赖，不能只隐藏按钮而留下可访问的账户或支付端点。

## 安全与隐私边界

- 分享链接等同于访问凭证，必须提示用户不要公开传播。
- 默认不在公开列表、搜索索引或站点地图中暴露体验。
- 头像、照片、音视频、二维码可能包含个人信息；创建前告知短期存储、可删除和自动过期规则。
- 校验上传 MIME、文件签名、体积、数量；拒绝可执行文件和不支持格式。
- 限流创建、读取、上传和删除接口；防止令牌枚举和滥用。
- 分享页面不应把付款二维码误呈现为平台担保或自动解锁；支付争议由双方自行处理。
- 上线前由实际运营主体确认适用的备案、隐私政策、投诉渠道和内容治理义务。免费不等于免除备案或个人信息保护义务。

## 部署边界

GitHub Pages 只能用于静态界面预览，不能承载需要跨设备短期分享的私密数据 API 和对象存储。中国大陆正式服务需要运营主体自行准备域名、境内云资源、备案、数据库、对象存储、定时清理和 HTTPS。未取得部署凭据与备案前，不得宣称已在中国大陆正式上线。

## 验收标准

- 女生无账号、无登录即可创建。
- 女生可以配置多关、金额、文字、照片/语音/视频和收款二维码。
- 生成的链接在另一台设备、微信内置浏览器中可以打开。
- 男生无需账号即可逐关体验；未完成前一关时后续关卡保持锁定。
- 扫码付款完全在外部应用发生；网站不读取付款结果、不自动解锁。
- 女生可主动删除；未完成 7 天过期；完成后 24 小时清理（如经确认采用该策略）。
- 过期/删除后，链接和媒体不可再访问。
- 全流程无注册、登录、平台订单、平台支付、会员、充值或分账入口。
