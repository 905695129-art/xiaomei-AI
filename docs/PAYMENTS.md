# 支付接入原则

## 创建订单
1. 服务端读取作品、关卡和创作者审核通过的商户配置。
2. 金额与收款主体均从数据库读取，客户端不可覆盖。
3. 创建 pending 订单，再向支付渠道创建支付单。
4. 返回支付渠道生成的支付参数。

## 支付回调
校验签名、时间戳、重放保护；必要时主动查询支付平台；核对商户号、金额、币种、订单号和交易状态；在数据库事务中幂等更新订单并授予关卡权限；记录支付事件。

## 收款主体
每位创作者独立收款，必须使用支付机构正式支持且审核通过的商户/平台结算机制。微信平台收付通、支付宝平台/分账产品需按官方准入条件申请，不承诺个人账户一定可接入。当前未配置商户凭据，支付保持关闭。

## 当前 MVP：创作者收款码与自助确认（非平台支付）

- 创作者可在作品编辑页上传自己的收款码；图片经过服务端解码与安全处理，二维码以无损 PNG 存储，避免有损压缩影响扫描。
- 买家按关卡逐一查看价格和收款码；确认收款人及金额后，自行完成转账，再点击“我已按约定完成转账，继续解锁”。
- 服务端只记录 `journey_level_unlocks.confirmation_method = self_attested_transfer`，并按买家匿名会话隔离。每一关单独确认，前一关仍需完成互动后才能进入下一关。
- 该记录不是 `orders.status = paid`，不是平台支付成功，不生成平台订单或商户结算记录。平台没有通过静态收款码核验实际到账。
- 该模式属于双方信任确认，存在未付款自助解锁、错付、退款争议等风险；上线前必须完成运营模式、收款主体、消费者权益和中国大陆适用法律的专项审查。若要求平台保障付款真实性，必须改为合规支付机构的服务端验签回调流程。
- 不得在 UI、订单、财务报表或宣传中将自助确认表述为“已支付/平台已收款/支付已验证”。

## 免费关卡

- 创作者可将单关金额设置为 `0`，体验者看到明确的“免费”标签；免费关卡不要求收款码，也不会创建自助转账确认或平台订单。
- 免费关卡仍遵循逐关顺序：只有前一关完成互动后才可打开；打开后可正常发送回应并记录完成进度。
- 价格为正数的关卡仍按本文件的自助确认边界处理；静态二维码不是平台验款或托管支付。
