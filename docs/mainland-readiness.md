# 中国大陆上线准备与验收清单

本文用于把 Heart Studio 从当前 Next.js 项目部署到中国大陆用户可稳定访问的生产环境。它是工程清单，不构成法律意见；网站实际服务类别、经营模式和资质要求，须由运营主体向接入云厂商、属地通信管理局及专业法律顾问核实。

## 0. 当前状态

- Next.js 应用、PostgreSQL schema、Docker Compose、健康检查、创作者账户、作品编辑、分享页、关卡互动回应等代码已存在。
- `/api/orders` 当前明确关闭真实支付，返回 `503 PAYMENTS_NOT_CONFIGURED`。
- 隐私政策和服务条款仍是草案，不能视为可直接上线的正式法律文件。
- GitHub Pages 只承载静态演示，不是生产应用。
- 仓库中没有可供代填的域名、备案主体、云账号、生产数据库凭据、邮件服务密钥或对象存储密钥。

因此，当前不能宣称网站已在中国大陆正式上线。

## 1. 先确定运营主体与服务模式

上线前由运营方书面确认：

- 网站主办者是个人还是企业/其他组织；证件、负责人、联系电话和实际经营地址必须真实一致。
- 网站是否只提供免费互动体验，还是向用户提供有偿的信息/网页服务、交易撮合或其他经营性服务。
- 用户支付的款项由谁收取、谁提供服务、谁承担退款和投诉责任。
- 平台是否向创作者收款后再结算，还是创作者直接与体验者交易。两者的支付、税务、消费者权益和平台责任不同。
- 服务内容是否涉及需要前置审批或专项资质的类别。

《互联网信息服务管理办法》区分经营性与非经营性互联网信息服务：非经营性服务依法办理备案；经营性服务实行许可制度。Heart Studio 的实际业务分类不能只凭产品名称或“金额仅作参考”判断，必须按真实运营模式核定。

## 2. 域名、云资源与 ICP 备案

建议使用中国大陆云厂商的中国内地地域云资源，并通过该云厂商备案系统提交网站备案：

1. 注册并完成实名认证的域名。
2. 选择支持 ICP 备案的中国大陆云服务器/云资源；香港或境外地域不能作为中国大陆服务器备案资源。
3. 确认主办者主体、网站名称、服务内容、负责人和联系方式符合接入商及属地管局要求。
4. 通过实际服务器接入商的备案系统提交备案材料；备案通过并取得备案号后，按规定展示备案信息。
5. 若业务被认定为经营性互联网信息服务，先核实是否需要增值电信业务经营许可证等许可，不得把普通 ICP 备案当作经营许可。
6. 若网站提供评论、公开发布或其他电子公告类功能，另行核实是否触发专项备案/许可要求。

**备案号未取得前，不应把指向中国大陆服务器的正式网站作为已合规上线服务对外运营。** 备案申请由运营主体和云厂商共同完成，代码仓库无法替代这一行政流程。

## 3. 建议的中国大陆生产架构

- Web：Next.js standalone 容器部署在中国大陆地域云服务器或容器平台。
- 数据库：PostgreSQL 使用受控私网访问；禁止把数据库端口直接暴露到公网。
- 图片/音视频：使用中国大陆对象存储；根据实际服务商要求配置访问域名、HTTPS、跨域规则、访问控制、生命周期和删除策略。
- 域名与 HTTPS：正式域名解析至大陆入口，使用可信 TLS 证书；HTTP 自动跳转 HTTPS。
- 邮件：选择可向目标用户稳定送达的邮件服务，验证发件域名、SPF/DKIM/DMARC；验证链接必须指向正式 HTTPS 域名。
- 日志与监控：记录必要的安全审计事件，设置告警、访问权限、保留期限和脱敏策略。
- 备份：数据库加密备份、对象存储备份/版本控制，并定期演练恢复。
- CDN/WAF：按实际流量和攻击面评估，不在没有测试的情况下把静态 CDN 缓存策略套用到登录态和私密内容接口。

所有生产环境变量只存放在云平台密钥管理或服务器受限环境文件中，不写入 Git、浏览器代码或公开日志。

## 4. 中国大陆用户数据与隐私保护

Heart Studio 会处理邮箱、账户凭据哈希、作品内容、上传照片/媒体、体验者回应、会话标识和订单信息。上线前必须：

- 明确每类数据的处理目的、必要性、保存期限、访问人员和删除机制。
- 对上传照片、语音、视频及可能包含第三方个人信息的内容提供清晰提示；用户应有权删除其作品和媒体。
- 不把体验者的匿名回应误称为完全匿名：系统仍可能处理会话标识和必要的安全日志。
- 对私密关卡内容实施服务端鉴权；公开接口不得返回尚未解锁的私密内容。
- 采用最小权限、强密码哈希、HttpOnly/Secure/SameSite Cookie、CSRF/来源校验、速率限制、备份加密和安全日志。
- 制定个人信息主体请求处理流程，包括查询、复制、更正、删除、撤回同意和账户注销。
- 若使用境外邮件、对象存储、分析或客服服务，先评估是否构成个人信息出境，并完成适用的告知、单独同意、评估/合同或其他法定程序；优先评估将中国大陆用户的账户数据和媒体存储在境内。
- 隐私政策和服务条款必须由真实运营主体补齐名称、地址、联系方式、数据处理细节、退款/投诉规则并经法律审查。

依据包括《个人信息保护法》和《网络数据安全管理条例》。具体义务应结合运营规模、数据类型和实际处理方式判断。

## 5. 支付与商业化上线闸门

当前真实支付保持关闭，这是有意的安全措施。不能用静态二维码、客户端按钮或“模拟支付成功”作为真实收款。

在开放支付前，至少完成：

- 确定合法收款主体、业务类目、商户号和支付服务商准入。
- 由支付服务商确认 Heart Studio 这种创作者发布互动内容、逐关定价的业务是否符合其类目和平台规则。
- 确定平台自营、服务商/子商户或其他合规结算模式；不得未经批准代收后向个人随意分账。
- 服务端创建订单，金额、币种、创作者、作品和关卡均从数据库读取，不能信任客户端传入金额。
- 验证支付回调签名、时间戳、随机数、证书/公钥和订单金额；采用幂等事件账本。
- 支付成功后在数据库事务中更新订单并发放对应关卡权限；前端跳转结果不能作为付款凭证。
- 实现退款、重复通知、订单超时、支付失败、对账、投诉和审计。
- 完成真实小额支付、退款和异常场景端到端验收后，才可开放收费。

## 6. 生产环境变量与部署验收

至少核对：

- `APP_URL`：正式 HTTPS 域名。
- `DATABASE_URL`：生产 PostgreSQL 私网连接。
- `POSTGRES_PASSWORD`：强随机且独立的数据库密码。
- `SESSION_SECRET`：独立随机密钥（若当前代码路径要求）。
- `RESEND_API_KEY`、`EMAIL_FROM`：若采用 Resend，必须使用真实服务端密钥和已验证发件域名；也可替换为经确认可用的境内邮件服务适配器。
- `STORAGE_ENDPOINT`、`STORAGE_PUBLIC_URL`、`STORAGE_REGION`、`STORAGE_BUCKET`、`STORAGE_ACCESS_KEY`、`STORAGE_SECRET_KEY`：启用封面上传时配置大陆对象存储对应参数。
- `PAYMENT_PROVIDER=disabled`：支付正式完成准入与联调前必须保持关闭。

验收顺序：

1. CI 通过，生产镜像构建成功。
2. 数据库迁移在空库和已有数据升级场景均成功。
3. `/api/health` 与 `/api/ready` 均返回 200。
4. 创作者注册、登录、邮箱验证、密码找回和退出其他设备可用。
5. 创建作品、编辑关卡、上传图片、保存、发布、复制链接可用。
6. 男方使用另一台设备/另一浏览器打开分享链接，逐关访问、提交回应。
7. 女方收件箱能看到回应，标记已读有效。
8. 私密关卡未完成前不可访问；归档作品不可公开访问；跨账户不能读取或修改他人作品。
9. 上传媒体、导出、注销、备份恢复和删除策略均通过测试。
10. 在中国大陆不同运营商网络及 iOS/Android 微信内置浏览器、主流手机浏览器进行真实访问测试。
11. 法律文件、备案展示、投诉渠道和运营主体信息完成审核。
12. 真实支付仍保持关闭，直至独立支付验收全部通过。
